# auth gcalendar — сайт для GitHub Pages

Статический сайт приложения с документами, которые требуются для OAuth-верификации в Google Cloud Console:

- главная страница с приветственным заголовком и описанием приложения;
- Политика конфиденциальности;
- Условия использования;
- русская и английская версии, переключатель языка в шапке.

Сайт не требует сборки, зависимостей и внешних CDN: только HTML, CSS и SVG.
Аналитики, рекламных cookies и сторонних шрифтов нет.

## Структура

```text
.
├── index.html              # главная (RU)
├── privacy.html            # Политика конфиденциальности (RU)
├── terms.html              # Условия использования (RU)
├── en/
│   ├── index.html          # главная (EN)
│   ├── privacy.html        # Privacy Policy (EN)
│   └── terms.html          # Terms of Service (EN)
├── assets/
│   ├── styles.css          # общие стили, светлая и тёмная тема
│   └── favicon.svg         # иконка сайта
├── .nojekyll               # отключает обработку Jekyll на GitHub Pages
├── robots.txt
└── README.md
```

Все ссылки относительные, поэтому сайт одинаково работает и в корне
`https://username.github.io/`, и в подпапке `https://username.github.io/repo/`.

## Локальный просмотр

Из папки проекта:

```powershell
python -m http.server 8000
```

Откройте <http://localhost:8000/>. Проверьте:

- главную и обе правовые страницы;
- переключатель RU / EN на каждой странице;
- мобильную ширину (например, 375 px) и тёмную тему;
- ссылки `mailto:` и внешние ссылки на политику Google.

Остановить сервер — `Ctrl+C`.

## Настройка в Google Cloud Console

В **APIs & Services → OAuth consent screen** (или **Google Auth Platform → Branding**)
укажите публичные ссылки:

| Поле | Значение |
|---|---|
| Application home page | главная страница сайта |
| Application privacy policy link | `.../privacy.html` |
| Application terms of service link | `.../terms.html` |
| Authorized domain | домен, на котором размещён сайт |

Требования Google, о которых стоит помнить:

- страницы должны открываться без авторизации, без ошибок и без редиректов на логин;
- ссылки должны вести на ту же информацию, которая указана в консоли;
- название приложения и его функции на главной должны совпадать с данными в консоли;
- для верификации может потребоваться подтвердить владение доменом в Google Search Console.

**Важно про `github.io`.** Домен `github.io` — публичный суффикс: подтвердить владение
им в Search Console нельзя, поэтому Google может не принять его как Authorized domain.
Если консоль не принимает адрес, подключите собственный домен к GitHub Pages:
создайте файл `CNAME` с вашим доменом, настройте DNS у регистратора и включите HTTPS
в **Settings → Pages**. После этого используйте адрес на своём домене во всех полях консоли.
Пока домен не подключён, сайт полностью работоспособен на `github.io` — это ограничение
касается именно верификации OAuth.

## Обновление документов

1. Измените текст в соответствующем HTML-файле (RU и EN отдельно).
2. Обновите дату в `page-meta` на обеих языковых версиях.
3. Если меняется состав данных или разрешений Google, синхронно обновите
   Политику конфиденциальности и описание на главной.
4. Закоммитьте и запушьте изменения — GitHub Pages обновится автоматически.

## Технические детали

- `.nojekyll` необходим, чтобы GitHub Pages отдавал файлы как есть и не пытался
  обрабатывать их через Jekyll.
- Тёмная тема включается автоматически по системной настройке (`prefers-color-scheme`).
- Стили поддерживают `prefers-reduced-motion` и корректную печать правовых страниц.
- Внешние ресурсы не загружаются, поэтому сайт работает и без CDN.
